**guard**（`scripts/research/fxid_cycle1/acquisition_guard.py`。合成の test だけで確かめた。取得はしていない）:

- **request の境界**: `str` そのもの（subclass は拒否）で、厳密な `YYYY-MM-DDTHH:MM:SSZ` だけを受ける。比較は parse した datetime どうしで行う。

## 9. Bid / Ask と取引 cost の問題

- **bid だけの data**（HistData M1 など）で gross を比べると、高回転の戦略を不当に有利に評価する（spread を払わない）。**Cycle 2 の主の data は bid / ask に限る。**
- **OANDA の BA の履歴**なら、過去の OANDA 自身の spread で net を出せる。過去と現在の cost の転用問題は、ほぼ消える。
- **他の source**（HistData の tick）は、その source の spread が OANDA と違う。保守的な cost model（OANDA の現在の pair × 時刻の平均 spread + 0.5 bp を下限とし、source の spread が広ければその値）を要する。
- **「gross で選び、現在の data で net を評価する」方式にも選択 bias がある。** gross で選ぶと、cost に弱い（高回転の）候補が優先される。net の評価の block が選択から独立でも、選ばれる候補の集合が cost の面で偏る。
- **対策の提案**（凍結しない）:
  - 帰無の閾値は gross の帰無の最大値から作る（「情報が無い」の帰無）。
  - そのうえで、**各候補の net の Sharpe をその閾値と比べる**。これは「net の平均 ≤ 0」の最も不利な点（gross = 0）での検定になる。
  - 選択の段階から net を使うので、cost に弱い候補は落ちる。
  - source の spread が使えない data では、この方式を取れないので、その data を主の選択に使わない。

## 15. max-T 統計基盤の技術検証

**run 1 の欠陥**（記録 `cycle1.json`、HEAD `d76303e`）:

- 4 回の検証（run 1 と run 2、試行 10 / 20）全てで 10% よりやや上（10.2・11.3・10.7・11.3%）。

- 採るなら、系列依存を保つ帰無（block 単位の符号ランダム化など）と合わせて再較正する。
